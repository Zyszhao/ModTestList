# RimWorld 测试清单：编写与清理

游戏内面板来自 **TestList 模组**（`RimWorld/Mods/TestList`）：它扫描**已启用模组根目录**下的
`TestList/`，把每个 Markdown 标题变成可标记的测试项，结果写回同目录的 `<文件名>.feedback.md`。

| 可以做 | 不要做 |
| --- | --- |
| 创建/编辑 `TestList/*.md`、`*.xml` | 手写 `*.feedback.md`（那是游戏的输出） |
| 读 `.feedback.md` 判断测过没有 | 改 `.feedback.md` 里的 `Status` 冒充测试结果 |
| 按结果删除（**通过项优先删**）、归档测试项 | 改已测项的**标题文字或文件名**（换 id、丢标记，见 §3） |

目标模组的 `AGENTS.md` 与本文冲突时**以项目指令为准**：项目不关心存档兼容性 → 不写「存档/读档」
类测试项；项目说"仅当我要求时才调用 GABS 测试" → 只写清单、别自己开游戏；项目有提交/文案/本地化
规范 → 照做。若它要求"完成后告诉用户要手动测什么"，就把那些内容写进 `<模组根>/TestList/xxx.md`，
而不是只回一段聊天文字。

## 1. 清单放在哪

- 必须是**模组根目录**下的 `TestList/`（与 `About/` 同级，大小写不限），可再套一层子文件夹，更深扫不到。
- 只读 `.md` / `.markdown` / `.xml`；单文件 > 4 MB 跳过；只有**已启用**的模组会被扫描。
- `.feedback.md`（或首行是 `<!-- TestList feedback`）是输出，不会被当输入读回；空文件仍会列出（0 项）。
- **`/TestList` 之外的文件永不被读取**：示例/参考清单别放进 `TestList/`，否则会混进真实清单
  （本模组的排版示例在 `Verify/fixtures/防空系统.md`）。
- 文件名 = 面板里的分组名，起个有意义的名字（别叫 `test.md`）。

## 2. 怎么写（Markdown：一个标题 = 一项）

```markdown
# 防空系统验证清单          ← 文档标题，也是可标记项
## 一、SAM 发射器            ← 分组标题同样可标记，写成分组名而非"待测试"
### 1. 未加油时不可发射       ← 一项说清一个可判定结论
- 建造 SAM 发射器，燃料保持 0
- 触发一次空投袭击
预期：`Ready` 为 false，不绘制弹体，钢铁不被消耗。
```

- 标题：一行一个可判定结论，用源码真实符号名（`` `CompRukayaSAMLauncher` ``），不要"测试一下"。
- 正文：`-` 分点写步骤，单独一行 `预期：` 给可观测结果（数值/日志字样/视觉）；可内嵌代码块、
  表格、嵌套列表。标题里的 `**粗体**`、`` `代码` ``、`[链接](url)` 在面板里只留文字。
- 解析：`#` 后必须有空格；```` ``` ````/`~~~` 代码块与 `<!-- -->` 注释里的 `#` 不算标题；Setext
  下划线（`===`/`---`）算标题。标题层级会拼成 `Path`（`文档 / 分组 / 测试项`），用于反馈定位。
- 篇幅：一次功能实现 **15~40 项**（<10 常漏边界，>60 滚不完）。覆盖正常路径、边界/极值、错误路径、
  性能、与其它模组共存；**只写源码里确实存在的功能**（先读 `.cs` / `Defs/*.xml` 确认）。

XML：① 直接把带 `<defName>`/`<label>` 的 Def 文件丢进 `TestList/`，每个顶层元素成一项；
② 专用清单 `<TestList><Test><Title>…</Title><Steps>…</Steps><Expect>…</Expect></Test></TestList>`，
标题字段取 `Title`/`Label`/`Name`/`Description`/`Desc`/`Steps`/`Expect`（不区分大小写）或 `Label`
属性，嵌套 `<Test>` 生成父子项。XML 出错会自动回退按 Markdown 解析。

## 3. id 稳定性（决定什么能改）

`md` 的 id = 「文件名 + 标题所在行号 + 标题原文」的 SHA1（XML 同理，末项换成 defName/路径）。游戏
靠 `<!-- testlist:id=… -->` 把标记与测试项对应起来，所以：

- ❌ 改**标题文字**、改**文件名**、在标题**之前**增删行 → 换 id，旧标记丢失
- ✅ 改标题下的正文、在文件**末尾**追加项、插入 HTML 注释
- **删掉任何一项，都会让它后面所有项的 id 变化**（行号变了）→ 那些项的标记作废
- 必须改标题时：先让用户保留原 `.feedback.md`，改完由人把标记迁到新 id（或接受重测），**不要偷偷改**

## 4. 读结果：`.feedback.md`

每个 `X.md` 在同目录生成 `X.feedback.md`，每个模组的 `TestList/` 下另有一份合并的 `TestList.feedback.md`。

```
<!-- TestList feedback v1 -->     ← 首行固定（UTF-8 无 BOM、LF）
<!-- testlist:id=md:be67ff19… -->
- Title: 一、建造与启用
- Path: 防空系统验证清单 / 一、建造与启用
- Status: pass                    ← pass | fail | untested，唯一权威结论
- Updated: 2026-10-07T13:55:48Z
- Feedback: -                     ← "-" = 没写；换行转义成 \n 写在一行里
```

- 定位优先用 `Path`（标题可能重名）；`Status` 是唯一权威结论，手工改它属于伪造测试结果。
- 统计：`pwsh -NoProfile -File "<Mods>/TestList/tools/analyze-feedback.ps1" -Path "<模组>/TestList"`
  （`-OnlyFail` 只看异常，`-Format Markdown` 出报告）；没有该脚本就按 `- Status:` 手动计数。

## 5. review + 清理（默认：通过项直接删）

> **确认无误的测试项默认从清单移除**：`Status: pass` 且反馈没指出残留问题。review 就顺手瘦身，
> 清单只留 `fail`、`untested` 和极少量回归项 —— 通过项留着只会让面板越来越长。

| 状态 | 动作 |
| --- | --- |
| `pass` | **默认删除**（不要以"以后可能还想看"为由保留） |
| `pass` 但反馈有值得长期保留的说明 | 先把要点挪进 `回归.md`，再删原项 |
| `fail` | **保留**，把反馈正文整理进该项正文的"已知问题" |
| `fail` 已修复 | 移进 `回归.md` 作回归项 |
| `untested`（功能在） | 保留 |
| `untested`（功能已废） | 删除 |

回归清单只收"容易再次坏掉"的少数断言，**5~15 项封顶**：存档兼容性、数值平衡、跨模组交互值得收；
一次性排版/贴图检查直接删。

顺序：① 读 `.feedback.md`（别读源清单猜结果）→ ② 汇报"删 N / 留 M / 转回归 K"并**直接执行**
（只有拿不准某项是否该留作回归项才问一句；汇报里列出被删项的标题）→ ③ 改 `TestList/*.md`
→ ④ 删掉已失效的 `.feedback.md` → ⑤ 提醒用户点「重新读取」。

- **必须在 RimWorld 退出后改**：运行中游戏会持续写 `.feedback.md`，可能与你的修改互相覆盖。
- 改前建议先提交一次 git：源清单能靠版本控制找回，`.feedback.md` 是 gitignore 的个人数据，删了找不回。
- 删除会让后面各项的 id 作废（§3），所以第 ④ 步等于整份重来：**保留下来的 `fail`/`untested` 项要
  重新标记一次**；想少丢标记就先删靠后的项，排在它前面的项行号不变。
- **不要重排编号**（`1.` `2.` 跳号无所谓；编号属于标题，重排 = 全部重测）。更稳的做法：别用序号做标题前缀。

## 6. 自检

- [ ] 在模组根 `TestList/` 下；文件名有意义
- [ ] 每个标题可判定、正文有 `预期：`；功能确实存在（已读源码 / Def）
- [ ] 覆盖边界、错误路径、存档读档（项目不关心则跳过）
- [ ] 未改已有项的标题文字 / 文件名；未手写、未手改 `.feedback.md`
- [ ] 已删掉 `pass` 项（只留 `fail` / `untested` + ≤15 项回归），并删掉失效的 `.feedback.md`
- [ ] 已告知用户：游戏内点「重新读取」（或重启）才生效

## 7. 常见坑

| 现象 | 原因 |
| --- | --- |
| 面板里没有清单 | 模组没启用 / `TestList` 不在模组根 / 忘了点「重新读取」 |
| 示例清单混进真实清单 | 示例 `.md` 放进了某个 `TestList/` —— 要放到 `/TestList` 之外 |
| 测试项没出现 | `#` 后没空格；或该行在代码块 / `<!-- -->` 注释里 |
| 标记全丢 | 改了标题文字、文件名，或标题之前的行数 |
| 一个文件出现两次 | 同一模组里既放了 `TestList/` 又有嵌层的同名文件夹 —— 只放一个 |
| 改完没生效 | 游戏内改清单要点「重新读取」；改 `.cs` 要重启游戏 |

格式细节（id 算法、解析边界、完整示例）见 `<Mods>/TestList/Verify/docs/format-spec.md`，与本文冲突时以它为准。
